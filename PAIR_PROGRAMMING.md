# Prática XP: Pair Programming (Adaptação)

O Pair Programming tradicional envolve dois desenvolvedores dividindo o mesmo computador, alternando entre os papéis de *Driver* (quem digita) e *Navigator* (quem revisa estrategicamente).

## Estratégia de Adaptação (Desenvolvimento Individual)

Como estou realizando o projeto individualmente, adaptarei os preceitos do Pair Programming utilizando as seguintes técnicas:

1. **Rubber Duck Debugging (Pato de Borracha):**
   Atuarei como *Driver* ao escrever o código e, em pausas sistemáticas a cada funcionalidade, assumirei o papel de *Navigator* explicando o código em voz alta (ou utilizando documentação em comentários) para justificar a lógica implementada. Isso emula a revisão crítica imediata do Pair Programming.

2. **Uso de IA como Navigator (Thought Partner):**
   Utilizarei ferramentas de Inteligência Artificial no papel de *Navigator*. Ao finalizar a lógica complexa de uma funcionalidade (ex: a manipulação do banco de dados para o Histórico do Perfil de Usuário), submeterei o trecho à IA para revisão de segurança, performance e code smell, emulando o feedback de um colega de trabalho.
